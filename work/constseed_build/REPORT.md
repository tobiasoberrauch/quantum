# Benchmark I — constant-seed (pwq3) invsqrt circuit

Foundation artifact: a **correct** kickmix circuit implementing the independently-verified
constant-seed numerical model (`work/invsqrt_constseed_model.py`, `seed_mode='pwq3'`,
`n1_frac=16, n2_guard=24, out_frac=26`). Correctness first; cost optimized only where it clearly
wins on `score = Q·C`. No SOTA-chasing. The seed is loaded from a **lookup table (QROM)** rather
than the original Horner workspace, which removes 126 qubits from the Newton peak.

## Lookup-table seed (the round-1 change)

`S = top8(r0)` is a function of the interval-muxed address. Analysis over the full domain
(`make_rom.py`) showed:
- circuit-S == model-S: **0 mismatches / 3,133,452 x** (AB=18 integer arithmetic ≡ model float);
- circuit-k == model-k: **0 mismatches**;
- **S depends on (interval, k), not k alone** — 0/128 k-values are constant across intervals;
- only **128 distinct S values** exist (S = 1/sqrt(M)·2⁸, M∈[1,4) ⇒ S∈[128,256), monotonic).

So the ROM is **512 entries** keyed on `addr = inter·128 + k`, where `inter = 2·top + (t_a⊕t_b)`
(the 4 intervals) and `k` is the existing 7-bit muxed sub-address. `build_constseed_circuit.py`
embeds `ROM_TABLE` (generated by `_seed_S(inter,k)`, bit-identical to the old Horner output).

Circuit wiring: `_select` → `_build_k` (unchanged) → form 9-bit address `[k[0..6], t_a⊕t_b, top]`
→ `init_lookup(ROM_TABLE, address, S)` … Newton … `del_lookup(ROM_TABLE, address, S)`. The lookup is
compute-then-uncompute, so it is **phase-safe** (no `reset`, sidestepping the R-op phase gotcha).
This deletes `coefs` (4×18) + `temps` (3×18) = **126 qubits** from the simultaneous-live peak.

### QROM cost (measured, `measure_lookup_cost.py`)
A standalone `init_lookup`+`del_lookup` on the real 512×8 table (9-bit addr, 8-bit target) costs
**551 static CCX**, 0 T, 0 rotations. It replaces the Horner seed's ~1404 CCX, so the lookup seed
nets **−853 CCX** *and* removes 126 qubits — a win on both axes versus the raw build
(9434→8581 CCX, 509→384 Q).

### Q<350 tradeoff (why the primary is 384, not <350)
To push peak Q below 350 the two **persistent Newton#1 product registers** (`prod_q1`=34,
`prod_p1`=24) must also leave the Newton#2 peak, which forces Newton#1's multiplies to be
**transient** (rebuild+clear per call = 4× row-adds instead of 2×). Measured hybrid: **Q=324**
(<350 ✓) but **CCX=11315** (>10000 ✗) and **ratio 0.555×** — *worse* score than the all-persistent
lookup (0.614×). Newton#1's multiplies are wide (x is 22 bits), so the transient penalty (+2734 CCX)
outweighs the Q saving (−60) under `score = Q·C`. Hence: **Q<350 is reachable only by trading away
score**; the all-persistent lookup (Q=384) is the better submission. Reaching Q<350 *and* low CCX
needs a cheaper Newton#1 (narrower cutoffs or a different multiplier), which would alter the
validated arithmetic — out of scope here.

## Pipeline (integer truncation matching the model exactly)

1. **normalize** — `x → x_norm = x << 2s`, unary flags = leading-zero-pair count `s`.
2. **seed (lookup)** — `k` = 7-bit interval-muxed slice of `x_norm`; `inter = 2·top+(t_a⊕t_b)`;
   `S = ROM[inter·128+k]` via reversible `init_lookup`/`del_lookup`.
3. **Newton #1 (n1=16)** — `SS=S²; Q1=(x_norm·SS)>>20; C1=3·2^16−Q1; P1=(S·C1)>>8`.
4. **Newton #2 (g=26)** — `sq2=P1²; Q2=(x_norm·sq2)>>28; C2=((3·2^26)−Q2)>>1; P2=(P1·C2)>>16`
   (folded form `(P1<<10·C2)>>26`).
5. **denormalize + phase** — `y1=P2<<s` (F=37 bits); per-bit `Z_POW` of `y1/2^37` turns; then exact
   reverse uncompute so `x` is restored and every scratch qubit returns to `|0>`.

## Cost breakdown (primary: lookup, all-persistent)

- **Q = 384** = peak live qubits, inside Newton #2: `x(22) flags(10) scratch(34) sel(2) k(7) S(8)
  inter_low(1)` + Newton#1 `SS(16) C1reg(18) P1(17) prod_q1(34) prod_p1(24)` + Newton#2
  `y1(37) sq2(34) C2reg(28) prod_q2(29) prod_p2(31)` = 351 logical + ~33 kickmix ancillas = 384.
  (The raw build's peak had the extra `coefs(72)+temps(54)` = 126 qubits here.)
- **static CCX = 8581**, T = 1, rotations (h4+) = 34.
- **C = 8812** = mean Toffolis (8581) + T/4 + rotation synthesis (~228); `rotation_eps = 1.74e-12`.
- **score = 384 × 8812 = 3,383,896** (full run).

### Why persistent products (kept)
Column-truncated multipliers either (a) rebuild+clear a **transient** pool every use → 4× row-adds,
or (b) keep a **persistent** register built once forward / cleared once inverse → 2× row-adds. (b)
cuts CCX (transient 15656 → persistent 9434 in the raw build). Because `score = Q·C`, the lower C
pays for the extra Q.

## Correctness

- Reproduces the model's **exact** integer pipeline; combined worst err/tol **0.5139** (≤ 0.6) —
  verified full-domain (`verify_full_lookup.json`, `status: PASS`). The value is **bit-identical**
  to the raw build because only the seed *loader* changed, not the arithmetic.
- Column cutoffs (from `find_cutoffs.py`, validated against the model) keep product columns ≥ L so
  dropped low columns carry < half an LSB:

| multiply | shift | L | W (=sh+out−L) |
|---|---|---|---|
| Q1 = (x_norm·SS)>>20 | 20 | 3 | 34 |
| P1 = (S·C1)>>8 | 8 | 1 | 24 |
| Q2 = (x_norm·sq2)>>28 | 28 | 26 | 29 |
| P2 = (P1·C2)>>16 | 16 | 12 | 31 |

  `AB=18` is the minimum internal precision matching the model exactly (AB≤16 fails). A pure
  no-cutoff build measured 2.32 worst/tol (FAIL) — truncating low columns drops carries the exact
  products keep.

## Gotchas discovered (do not re-fix)

1. **`builder.reset()` corrupts the tracked phase.** kickmix's `R` op does `phase ^= qubit & rng`
   (`sim/sim.h`) — a data-dependent half-turn whenever the reset qubit is `|1>`. `del_and` is
   phase-safe only because its HMR phase-flip is cancelled by the `CZ` correction; a bare reset has
   no cancellation. **Never reset a qubit that may be `|1>` under phase tracking.** (The lookup
   seed avoids this entirely — it clears via `del_lookup`, not `reset`.)
2. **Seed workspace could not be freed before Newton (raw build).** `S=top8(r0)` was cleared
   phase-safely only while `coefs[0]` still held `r0`; restoring B,C mutated `coefs[0]`. This pinned
   the raw peak Q at 509. **Resolved by the lookup seed** (S cleared by `del_lookup`, no accumulator
   dependency).
3. **`_add_row` scratch invariant**: scratch fully `|0>` between calls; unique indices per call. The
   shared 34-qubit pool is safe because each `_add_row` cleans its own products.
4. **Transient wide multiplies are expensive.** Making Newton#1's multiplies transient to cut Q
   adds ~2734 CCX (they span 22-bit x) — a net score loss. Don't transient-ify wide multiplies to
   buy Q unless CCX budget allows.

## Deviations from the optimistic estimate (~1.8× / ~4800 CCX)

Best ratio ≈ **0.614×** (lookup), still worse than the reference's 1.0×. Causes:
1. **Two Newton steps** (model n1+n2) vs the reference's single NR step ≈ double the multiply work.
2. **Exact-arithmetic requirement** → column cutoffs widen product registers (up to 34 bits).
3. **Persistent products** (to halve CCX) keep wide registers live across Newton → Q floor ~384.

These are properties of the *validated spec*, not builder bugs; the spec was not modified.

## Future optimizations (not done)

- **Cheaper Newton#1** (narrower cutoffs / a smaller multiplier) to reach Q<350 *without* the
  transient CCX penalty — the only path to clear the ideal Q bar while keeping ratio ≥ 0.614×.
- **Single Newton step** if the tolerance budget allows (roughly halves multiply CCX) — changes the
  validated model, out of scope.
